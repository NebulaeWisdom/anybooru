# e621ng 客户端用法

`E621` 用于访问运行 e621ng 引擎的站点。`e621.net` 与安全内容镜像 `e926.net` 是同一套程序的两个部署：路由相同、返回结构相同，只有站点地址与内容范围不同。`E621('e621')` 连前者，`E621('e926')` 连后者。

本页说明这个类怎么用。18 个方法各自给什么、返回什么字段，见[方法参考](e621-api.md)；“我要做某事 → 用哪个方法”见[能力入口](e621-capabilities.md)；上游文件与行号依据见[契约审计附注](e621-contract-notes.md)。

## 第一次调用

```python
from anybooru import E621

with E621('e621') as client:  # 站点地址与请求设置来自包内 anybooru.json
    posts = client.post_list(tags='rating:s', limit=2)
    # GET https://e621.net/posts.json?tags=rating%3As&limit=2
    # 服务端返回 {"posts": [...]}；库把里面的数组交给你，posts 就是那个列表。
    # 每个帖子是嵌套对象：file{width,height,ext,size,md5,url}、score{up,down,total}、
    # tags{general,artist,contributor,copyright,character,species,invalid,meta,lore}。
    print([(post['id'], post['rating'], post['file']['ext']) for post in posts])
    print(client.last_call['status_code'], client.last_call['url'])
```

本轮按字面执行取回两帖，编号 `6715278`、`6715276`，都带 `rating=s`。记录见[文档代码复核](verification.md#文档字面代码复核2026-09-18)。

这行调用按 `rating:s` 过滤、每页两条。`posts` 是 Python 列表，不是带 `posts` 键的字典：默认分支下 `post_list` 会从服务端的 `{"posts": [...]}` 里取出数组，不需要你再写 `['posts']`。什么时候相反（你拿到整个字典）见下面的“返回值”表与[方法参考](e621-api.md)。

## 构造与配置

签名（不是可运行代码）：

```text
E621(site_name=None, site_url=None, username=None, api_key=None, proxies=None,
     *, config_file=None, timeout=None, user_agent=None)
```

| 参数 | 怎么用 |
| :--- | :--- |
| `site_name` | 配置 `sites` 段里的键；`E621('e621')` 用 `https://e621.net`，`E621('e926')` 用 `https://e926.net` |
| `site_url` | 直接给站点根地址，覆盖 `site_name` 里的地址；自建实例或未写进配置的站点用这个 |
| `username` | HTTP Basic 的用户名；省略时取该 `sites` 条目的 `username` |
| `api_key` | HTTP Basic 的密码（e621ng 的 API key）；省略时取该条目的 `api_key` |
| `proxies` | 代理字典；省略时取配置 `request.proxies`（包内默认是空对象，不走代理，也不读环境变量） |
| `config_file` | 另一份配置文件的路径；省略读包内 `anybooru/anybooru.json`；给错路径直接抛 `FileNotFoundError`，不回落 |
| `timeout` | 请求超时秒数；省略时取配置 `request.timeout`（包内为 `30`） |
| `user_agent` | 覆盖 User-Agent；省略时取配置 `request.user_agent`（包内为 `Anybooru/0.1.0.dev1`） |

站点条目只有三个键：`url`、`username`、`api_key`。没有 `password`、`hash_string` 或 API 版本开关，因为 e621ng 用 API key 做 Basic 密码，也没有路径版本参数。

`examples.e621` 段只服务仓库里的示例脚本（站点名、查询、条数、调用间隔）。教学代码不要依赖它，直接写字面参数，例如示例脚本的 `post_query` 等价于 `client.post_list(tags='rating:s', limit=2)`。构造签名见 [configuration.md](configuration.md)。

## 认证

`username` 或 `api_key` 任一非空，每个请求就带 `Authorization: Basic <base64(用户名:API key)>`。两项都空才是匿名请求。上游把 Basic 凭据按第一个 `:` 切开当登录名与 API key 校验。客户端不判断凭据是否有效：无效或不全由服务端以 `401` 拒绝，不会悄悄退回匿名。

上游也接受 `login` + `api_key` 查询参数，但那条路径要求同源请求才跳过 CSRF 校验，本库不用它。需要成员身份的方法（`related_tag`、`related_tag_bulk`）匿名会得到 `403`，见[认证](authentication.md#e621ng-系站点)。

## 通用 request()

签名（不是可运行代码）：

```text
request(method, path, *, params=None, data=None, files=None, envelope=None)
```

它是 18 个原生方法的底座，也是没被封成方法的其它只读路由的出口。下面的调用取回列表端点，但**不**替你取出 `posts`，你拿到的就是服务端原样的字典：

```python
from anybooru import E621

with E621('e621') as client:
    body = client.request('GET', 'posts', params={'tags': 'rating:s', 'limit': 1})
    # GET https://e621.net/posts.json?tags=rating%3As&limit=1
    # 返回 {"posts": [...]}；body 里只有 posts 一个键，body['posts'] 是 1 条帖子的列表。
    print(list(body))
    print(body['posts'][0]['id'], body['posts'][0]['file']['md5'])
    # 本轮输出：顶层 ['posts']，首帖 6715278，file.md5 为 64df9ed638c90c16070a3e63f67aa129。
```

- `method`：`'GET'`、`'POST'` 等 HTTP 方法。本家族的 18 个原生方法全是 `GET`；写路由要你显式用 `request()`。
- `path`：相对站点的路径，开头的 `/` 会去掉。不带 `.json` 时客户端补上（`'posts/random'` 与 `'posts/random.json'` 等价）。
- `params`：查询参数字典，编码规则见下一节。`None` 的项不发。
- `data`：请求体。没有 `files` 时按 JSON 发送。`None` 的项不发，空列表照样发出。
- `files`：非空时请求体改成 multipart 表单，字段名用字面键（例如 `upload[files][0]`）。
- `envelope`：只接受**一个键名**，用来从响应字典里取出那一项。原生方法按上游分支决定用哪个键（`posts`、`post`，或哪个都不传表示原样返回）；键不存在直接抛 `KeyError`，不会换别的键去找。
- 路径里的变量要你自己转义。原生方法已内置转义（标签名、画师名、wiki 标题整段转义，所以 `wiki_page_show('help:api')` 发出的地址是 `wiki_pages/help%3Aapi.json`）。
- 不重试、不翻页、不补参数。网络错误、`429`、`5xx` 全部抛给调用者。请求头固定为配置里的 `User-Agent` 与 `Accept: application/json`，会话不读环境变量。

## 参数编码

查询串与表单共用 Rails 的括号写法：嵌套字典 → `a[b]`（例如 `search[name_matches]=anthro`），列表 → 重复键 `a[]`，布尔 → 小写 `true` / `false`，`None` 不发。

**列表方法**把过滤条件放进 `search` 字典，整包变成 `search[...]`：

```python
from anybooru import E621

with E621('e621') as client:
    tags = client.tag_list(search={'name_matches': 'anthro'}, limit=2)
    # GET https://e621.net/tags.json?limit=2&search%5Bname_matches%5D=anthro
    # 返回标签对象列表；每项有 id、name、category、post_count。
    print([(tag['name'], tag['post_count']) for tag in tags])
```

**帖子查询是例外**：`post_list`、`post_count`、`post_random` 没有 `search` 字典，过滤条件全部写成顶层 `tags` 元标签（`rating:s`、`wolf order:score` 等），`tags` 之外的项走顶层参数：

```python
from anybooru import E621

with E621('e621') as client:
    hit_count = client.post_count(tags='rating:s')
    # GET https://e621.net/posts/count.json?tags=rating%3As
    # 返回 {"count": 240001, "capped": true}（2026-09-15 实测，e621 与 e926 同值）。
    print(hit_count['count'], hit_count['capped'])
```

`page` 与 `limit` 是顶层参数，服务端自己分页与钳位：

- `page=2` 是第 2 页。
- `page='b6715096'` 取 id 小于 6715096 的记录。
- `page='a6715096'` 取 id 大于它的记录。
- 两种游标都按 id 从新到旧返回。
- `limit` 收 `0..320`，不传时每页 75 条；帖子用账号自己的每页设置。越界或非数字回 `410`。
- 其它分页细节见 [pagination.md](pagination.md)。

## 返回值与 last_call

原生方法把你实际会用到的那一层交给你。下表列出给什么、返回什么 Python 类型、对应服务端 JSON 哪一层：

| 调用 | 你拿到什么 | 服务端 JSON |
| :--- | :--- | :--- |
| `post_list(tags=..., limit=2)` | 帖子列表 | `{"posts": [...]}` 里的数组 |
| `post_show(6715096)` / `post_random(tags='rating:s')` | 一个帖子字典 | `{"post": {...}}` 里的对象 |
| `post_list(md5='b37f8af2b4508efb57cfeb08ef2ef5a1')` | 一个帖子字典；查不到时 `404` | `{"post": {...}}` |
| `post_list(tags='rating:s', limit=1, only='id,rating')` | 帖子列表，**字段没被裁**（仍是完整 25 键） | 数组本体，没有外层字典 |
| `post_list(tags='rating:s', limit=1, v2=True)` | 帖子列表，元素换成 18 键的新结构（`files`、`stats`、`tags` 是字符串数组） | 数组本体 |
| `post_count(tags='rating:s')` | `{'count': 240001, 'capped': True}` | 内联字典 `{"count": ..., "capped": ...}` |
| `tag_list(...)` / `artist_list(...)` / `comment_list(...)` / `pool_list(...)` / `note_list(...)` / `wiki_page_list(...)` | 相应对象的列表 | 数组本体 |
| `tag_show(...)` / `artist_show(...)` / `comment_show(...)` / `pool_show(...)` / `note_show(...)` / `wiki_page_show(...)` | 相应对象的字典 | 对象本体 |
| `related_tag(...)` | 列表；`related_tag_bulk(...)` 返回以标签名为键的字典 | 数组 / 对象（成员身份，匿名 `403`） |
| `request` 不指定 `envelope`，且成功响应没有正文 | `None`；原生帖子方法要求响应有 `posts` / `post`，不会把空正文改成空列表 | 无正文 |

非 2xx 一律抛 `AnybooruHTTPError`，带 `http_code`、`url`、`body`、`data`、`response`，见 [errors.md](errors.md)。

`last_call` 记最近一次请求的实际情况：`API`（相对路径）、`url`（含查询串的最终地址）、`status_code`、`status`、`headers`。要核对“参数究竟发成什么样”，打印 `url` 最快：

```python
from anybooru import E621

with E621('e621') as client:
    client.post_list(tags='rating:s', limit=2)
    # GET https://e621.net/posts.json?tags=rating%3As&limit=2
    print(client.last_call['status_code'], client.last_call['url'])
    # 200 https://e621.net/posts.json?tags=rating%3As&limit=2
```

## 查看请求失败的原因

图片编号不存在时，错误会带回实际 HTTP 状态和正文，不能把它当作一个空的帖子列表：

```python
from anybooru import E621, AnybooruHTTPError

with E621('e621') as client:
    try:
        missing_post = client.post_show(0)
        # GET https://e621.net/posts/0.json
    except AnybooruHTTPError as error:
        print(error.http_code)  # 404
        print(error.url)  # https://e621.net/posts/0.json
        print(error.data)  # 服务器给出的 JSON 错误内容
```

## 常见坑

1. **评级只有 `s` / `q` / `e`**：查询里的 `rating:` 取首字母判断，所以 `rating:safe` 等价于 `rating:s`。首字母不在词表里的值（例如 Danbooru 的 `rating:g`）被**整条丢掉**，不报错也不过筛——写错的表现是“返回最新帖子”，不是“报错”。
2. **帖子字段是嵌套结构**：`file`、`preview`、`sample`、`score`、`tags` 各自是对象。`tags` 是九个类别（`general`、`artist`、`contributor`、`copyright`、`character`、`species`、`invalid`、`meta`、`lore`）到标签名列表的字典。没有 `tag_string`、`file_url`、`media_asset` 这些 Danbooru 字段；按 Danbooru 的写法取字段会 `KeyError`。
3. **对当前身份不可见的帖子，键还在、值被置空**：`file.url`、`preview.url`、`preview.alt`、`sample.url`、`sample.alt` 只在可见时才有值，否则是 `null`。`file.md5` 与 `file.ext` 仍然来自模型。另一条序列化路径（模型自身的 `as_json`）才会连 `md5`、`file_ext` 两个键一起省掉，两条路径的差别见[附注](e621-contract-notes.md#sec-post-shapes)。
4. **`only=` 不是选字段**：只要它非空，上游就去掉外层字典直接给数组/对象，返回的每条仍是完整的 25 键旧结构。想换成新结构要用 `v2=True`（`files`、`stats`，`tags` 是数组或按类别分组的字典）。
5. **顶层 `random=True` 不改排序**：它只影响上游 `PostSets::Post` 的随机状态与页面呈现，查询本身不变。要随机排序用 `tags='order:random'`，或直接调 `post_random`。
6. **空的 `search` 值会触发 302**：上游对所有 `GET` / `HEAD` 请求先剔除空白的 `search` 项，只要有项被剔掉就回 `302` 到清理后的地址。客户端把 `None` 直接省略，但空字符串 `''` 会照发并触发这次重定向。
7. **`comment_list` 不是“全站最新评论”**：匿名看不到被隐藏的评论，也看不到评论被关闭的帖子的评论。没有 `search={'id': ...}` 时还会再套一层“置顶或评分达阈值”的过滤。`group_by='post'` 返回的是**帖子对象列表**（不是评论，也没有把评论嵌进去）。
8. **`post_count` 的 `count` 可能是下限**：查询撞上分页上限时 `capped=True`（实测 `240001` / `capped=True`）。计数路由是 `/posts/count.json`；Danbooru 的 `/counts/posts.json` 在 e621ng 不存在。
9. **`related_tag` 一族要成员身份**：`related_tag(search={'query': 'wolf', 'category_id': 0})` 匿名返回 `403`，正文 `{"success": false, "reason": "Access Denied"}`。两个方法的参数层级不同——`related_tag` 用 `search={'query': ..., 'category_id': ...}`，`related_tag_bulk('wolf', category_id=0)` 用顶层参数。
10. **`/help/api` 不是 `wiki_page_show` 的对象**：`wiki_page_show('help:api')` 请求 `/wiki_pages/help%3Aapi.json`，返回 wiki 页面。站点上的 `/help/api` 属于 `help_pages` 路由的另一种记录（HelpPage），本库没有为它封方法，需要时用 `request()`。

命名规律：`xxx_list(search=None, **params)` 列表与搜索，`xxx_show(id, **params)` 单条详情。本家族**没有原生写方法**；发帖、编辑、上传这类动作要自己用 `request()` 明确指定方法与请求体。

## 可运行示例

三个脚本都能匿名运行，支持 `--config`（换配置文件）与 `--site`（换站点，例如 `--site e926`）。省略 `--config` 时读包内配置，省略 `--site` 时取 `examples.e621.site`：

```bash
.venv/Scripts/python.exe examples/e621/list_posts.py --site e621
.venv/Scripts/python.exe examples/e621/browse_resources.py --site e621
.venv/Scripts/python.exe examples/e621/wiki_pages.py --site e621
```

脚本里的调用与教学写法一一对应，例如 `list_posts.py` 的三步就是：

```text
client.post_list(tags='rating:s', limit=2)        → /posts.json?tags=rating%3As&limit=2
client.post_show(posts[0]['id'])                  → /posts/<id>.json
client.post_random(tags='rating:s')               → /posts/random.json?tags=rating%3As
```

2026-09-18 在 e621.net 的真实匿名执行（`--config <配置文件>`、未传 `--site`）：15 次调用全部 `200`，三个脚本都退出 `0`、stderr 为空。

- `list_posts.py`：列表 `6715096` / `6715093`，详情 `6715096`，随机 `502758`，均 `rating=s`。
- `browse_resources.py`：标签 `7115 anthro`，画师 `126799 panzer_(p.z)`，评论 `10075334`（正文 229 字符），合集 `54791`，笔记 `506654`；每类都是先列表、再用列表首项的 id 取详情，共 10 次调用。
- `wiki_pages.py`：列表标题 `toriel` / `vodyanoy5`；`wiki_page_show('help:api')` 返回 `11224`，`is_locked=true`。

脚本只打印身份字段与计数，不打印媒体地址与评论/笔记正文。命令、URL 与状态码见[验证记录](verification.md#anybooru-改名后的复跑2026-09-18)。

## 边界与未实测

- 18 个方法里 16 个有匿名成功记录（15 个来自示例脚本、两个站点各跑一遍，外加两个站点的 `post_count`）；`related_tag` 只有匿名 `403` 记录，`related_tag_bulk` 一次请求都没有发过。两者的成员成功路径需要凭据，**未实测**。
- 返回形态复核覆盖：`post_list` 默认列表、`md5` 单帖、`only` 保留完整字段、`v2=true` 新结构、`post_count`；本轮还执行了 `comment_list(group_by='post')`，得到 5 个帖子对象，即使调用中给了 `limit=2`。未实测 `v2` 的 extended/thumbnail、按名称查标签/画师、`safe_mode`、旧式单数路径及全部写操作。
- e621ng 面没有原生写方法、没有管理/审核方法、没有抓 HTML 页面的方法；上游写路由与其它只读 JSON 路由要用 `request()` 自己调，排除清单见[能力入口](e621-capabilities.md)。
- 只覆盖 `e621.net` 与 `e926.net` 两个站点；e926 的实际过滤范围与可见范围由该站部署决定，不在上游仓库默认值里，也不能从上游仓库默认值推断。

不用 `with` 时，调用完请执行 `client.close()`。
